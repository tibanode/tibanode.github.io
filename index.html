§ 01 Vision

Medical AI has to operate within real infrastructure.

Hospital computing hardware varies. Reliable cloud access cannot always be assumed, and medical information requires careful handling.

An AI system should expose what the available hardware can actually support—not hide infrastructure constraints.

§ 06 Getting started

Local runtime

Getting started with tibanode. Run medical models locally.

tibanode is designed to make the path from hospital hardware to compatible local inference explicit.

  1. 01Inspect hardware

    Identify the compute, memory and runtime capabilities of the host machine.

  2. 02Verify compatibility

    Make model identity, hardware fit and validation state visible before inference.

  3. 03Run locally

    Serve inference within hospital-owned infrastructure through a local interface.

§ 08 Principles

Principles.

  1. 01

    Local first

    Patient inference should not require a remote inference service.

  2. 02

    Hardware is real

    The system should expose what a machine can and cannot reasonably run.

  3. 03

    Trust is visible

    Model identity, compatibility and validation state should be explicit.

  4. 04

    Hospitals first

    The system is designed around hospital infrastructure and clinical environments.
